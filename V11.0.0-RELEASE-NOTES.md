# JARVIS V11.0.0 — Feature Release

Every command and feature from V10.1.0 is unchanged and still present. Nothing was removed. This release only adds new functionality and wires in code that already existed in the project but was never connected to anything.

Verified: a direct diff against the V10.0.0 upload shows zero commands removed from `src/index.js` (56 to 63), zero command-engine actions removed from `src/core/commandEngine.js` (one added), and zero tools removed from `src/core/toolRegistry.js` (two added). The full test suite (12 tests across `test/v9-core.test.js`, `test/v10-tts.test.js`, and the new `test/v11-features.test.js`) passes.

## New features

**Reminders now survive a restart.** `jarvis remind` previously lived only in an in-memory `setTimeout`, so a Railway restart or redeploy silently lost every pending reminder. `config.reminders` — an array that already existed in the config schema but was never written to — now actually stores each reminder, and the bot rehydrates and reschedules any still-pending reminders on startup. A reminder that fires after a restart is labeled "recovered after a restart" so it's clear what happened.

**Server notes and personal preferences.** `src/core/memoryLayers.js` was a fully built module in V10 with no code calling it anywhere. It's now wired into six new commands:
- `jarvis note <text>` — save a persistent, server-wide note (admin only)
- `jarvis notes` — list saved server notes
- `jarvis clearnotes` — clear all server notes (admin only)
- `jarvis pref <key> <value>` — save a personal preference (any member)
- `jarvis myprefs` — view your saved preferences

These are distinct from the existing `jarvis remember`/`jarvis forget` commands, which store free-text facts fed into AI chat replies. Notes and preferences are structured key/value data any command can read directly, with no AI call involved.

**Generalized recurring scheduler.** The V10 daily-briefing loop (`config.ai.dailyBriefing`) is untouched — same code, same behavior. A second, independent scheduler loop now runs arbitrary jobs from `config.v9.scheduledJobs`:
- `jarvis schedule add <hour 0-23> <message>` — post a recurring message once a day, in the channel it was created in, at the given Cairo-time hour
- `jarvis schedule list` — show all scheduled jobs
- `jarvis schedule remove <job id>` — remove one

**Full case detail.** `jarvis case <id>` shows the complete before/after state, actor, target, reason, and reversibility of one journal entry. This data was already being recorded by the executor for every action — it just wasn't previously exposed for a single case.

**Activity spike detection.** `src/systems/analytics.js` now tracks a rolling per-minute message count per guild and can compare the current minute against the recent 10-minute baseline. `jarvis ratecheck` reports the current rate, baseline, and whether a spike is detected. This is informational only — it does not mute, kick, or otherwise moderate anyone; it only surfaces a signal a human moderator (or a future anti-raid integration) could act on.

**Unified tool registry.** The V9 structured command path's tool registry (`src/core/toolRegistry.js`) gained `clock` and `server.status`, matching what the AI chat path's separate tool dispatcher (`src/v8/tools.js`) already offered. The AI chat path itself is unchanged — this just makes the structured registry a more complete catalog for future use.

**Auto-refreshing dashboard.** The web dashboard (`DASHBOARD_ENABLED=true`) now refreshes itself every 20 seconds instead of requiring a manual reload. Every field it showed before (Discord/AI/voice status, per-guild member counts, moderation cases, AutoMod/Anti-Raid/lockdown state, top activity) is still there, unchanged.

## Compatibility

Existing guild config files upgrade automatically — `config.v9.scheduledJobs` defaults to an empty array via `normalizeConfig`, and existing reminders (if any were somehow present) are picked up the same way. No manual migration is needed.
