# JARVIS V8.2.5 — Moderation Separation Fix

## What changed

Natural-language moderation now keeps these Discord actions completely separate:

- **Timeout** — Discord communication timeout.
- **Text mute** — configured `muteRoleId`, used to prevent text/chat access.
- **Server mute** — Discord voice mute via `GuildMemberVoice#setMute`.
- **Un-timeout** — removes a Discord timeout.
- **Text unmute** — removes the configured text-mute role.
- **Server unmute** — removes a Discord voice mute.

## Natural-language examples

- `jarvis timeout Steve` → Discord timeout (10 minutes by default)
- `jarvis Steve swore at me, time him out` → Discord timeout
- `jarvis untime him out` → removes the most recent owner-created timeout
- `jarvis untime Steve out` → removes Steve's timeout
- `jarvis mute Steve` → **text mute**, not timeout
- `jarvis text mute Steve` → text mute
- `jarvis server mute Steve` → voice/server mute
- `jarvis voice mute Steve` → voice/server mute
- `jarvis unmute Steve` → **text unmute**
- `jarvis text unmute Steve` → text unmute
- `jarvis server unmute Steve` → voice/server unmute
- `jarvis voice unmute Steve` → voice/server unmute
- `jarvis remove Steve's timeout` → removes Steve's timeout

## Safety / permissions

Each action checks the permission it actually requires:

- Timeout: `ModerateMembers`
- Text mute: `ManageRoles` plus configured mute-role hierarchy
- Server voice mute: `MuteMembers` plus a member currently being in voice
- Ban/kick: existing Discord hierarchy checks

JARVIS no longer reports that the application lacks generic administrative permission when the real issue is simply that a natural-language action was not routed to the correct executor.
