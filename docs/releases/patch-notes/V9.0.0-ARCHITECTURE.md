# JARVIS V9.0.0 Architecture

## Request lifecycle

```text
Discord message / slash command
        ↓
      Router
        ↓
   Structured intent
        ↓
      Resolver
        ↓
 Permission + hierarchy checks
        ↓
 Confirmation / simulation
        ↓
     V9 Executor
        ↓
   Action Journal
        ↓
  Response + diagnostics
```

## Modules

- `src/core/commandEngine.js` — unified natural-language command routing.
- `src/core/resolver.js` — ambiguity-safe member/channel resolution and aliases.
- `src/core/permissions.js` — centralized Discord permission and hierarchy checks.
- `src/core/executor.js` — shared action execution for voice/moderation operations.
- `src/core/context.js` — short-lived multi-turn command context.
- `src/core/confirmations.js` — destructive-action confirmation state.
- `src/core/journal.js` — persistent V9 action history and reversible metadata.
- `src/core/awareness.js` — live server/voice state snapshots.
- `src/core/simulator.js` — dry-run planning.
- `src/core/toolRegistry.js` — controlled tools available to future AI planning.
- `src/systems/eventAwareness.js` — optional event-driven server awareness.

## Design rule

**AI interprets. Deterministic code resolves, validates, executes, and reports.**

The AI parser never receives permission to mutate Discord directly.
