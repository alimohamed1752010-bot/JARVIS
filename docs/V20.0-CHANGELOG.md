# JARVIS V20.0

## Local-first architecture

V20 keeps the existing Discord + Windows PC architecture, but changes the decision flow:

1. Deterministic allowlisted actions are recognized locally first.
2. Simple PC commands execute without a Gemini planning request.
3. Gemini is used only when local routing cannot safely resolve the request.
4. Relevant local Vault notes are retrieved before AI escalation.
5. The full Vault is never dumped into the prompt.
6. Live PC context is only queried when an AI escalation actually needs it.

## Local Vault

`vault/` is a human-editable, filesystem-based memory layer inspired by the Obsidian/CLAUDE.md architecture.

- `VAULT_INDEX.md` is the map.
- `user/` stores durable user preferences.
- `projects/` stores project knowledge.
- `instructions/` stores procedures.
- `memory/` stores durable recent memory.
- `knowledge/` stores optional reference notes.

Set `JARVIS_VAULT_PATH` to move the Vault elsewhere.

## Voice cost/latency change

V20 defaults to **local Windows TTS** through `System.Speech`.

- `JARVIS_TTS_MODE=local` is the default.
- `JARVIS_TTS_MODE=gemini` restores Gemini TTS.
- `JARVIS_TTS_GEMINI_FALLBACK=true` lets local TTS fall back to Gemini if local speech fails.
- `JARVIS_LOCAL_TTS_VOICE` can select an installed Windows voice by description.

STT remains Gemini-based in this release because the existing voice pipeline already uses it successfully. That means one Gemini request per voice transcription, rather than a second Gemini request for speech synthesis.

## Safety

The existing plan validation, permissions, risk checks, confirmations, execution and verification remain in place. Local-first does not grant the AI unrestricted Windows command execution.
